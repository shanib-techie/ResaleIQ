Three algorithms competed to price a used phone. One of them earned the job.

ResaleIQ predicts what a second-hand phone is actually worth from 1 million real resale listings. This page walks through how the model was built — including the two approaches that fell short before LightGBM took over.

What went wrong first

02 attempts before the working model

Random Forest was starved of trees and data R² 0.9497

Only 30 trees were grown, and the forest only ever saw a 200,000-row sample of the 1M-row dataset instead of the full thing. Random Forest builds every tree independently on a bootstrap sample, so a shallow forest averages over too few, too-similar trees — it plateaus early and never sees roughly 80% of the available listings.

XGBoost was capped too shallow, and the sample wasn't reproducible R² 0.9396

Trees were limited to max_depth=3, which is too shallow to capture interactions like "cracked screen + Poor condition + low battery health." Worse, the row sample used no fixed random_state, so re-running the notebook draws a different 200,000 rows every time — the score isn't even reproducible run to run.

LightGBM fixed both problems at once R² 0.9836

LightGBM grows trees leaf-wise instead of level-wise and bins features into histograms before splitting, so it trains fast even on the full 800,000-row training set — no subsampling needed. With 300 trees, a learning rate of 0.05 and max depth of 8, it captures the deeper feature interactions the other two missed, cutting average prediction error to about ₹1,699 on phones that average roughly ₹22,584.

What actually drives the price

LightGBM feature importance, split count

Zero-importance features — camera score, processor score, screen size, release year, 5G, OS type, city tier, seller type — were never chosen for a single split. That's not a data-quality issue; it means the model already explains resale price well enough from condition and demand signals that these attributes add no further information on top.
